# Coder 工作区使用说明

Coder 工作区提供了一个可直接使用的 Linux 开发环境。你可以用本地 VS Code 或网页版 Code 连接工作区，在里面写代码、运行程序、调试项目，并配合 AI Agent 提升开发效率。

## 1. 为什么推荐使用 Linux 工作区？

很多开发工具、构建工具和 AI Agent 都更适合在 Linux 环境中运行。把开发环境放到 Coder 工作区中，主要有几个好处：

- **环境更统一**：团队成员进入工作区后，使用的是相同的基础环境，减少“我这里能跑、你那里不能跑”的问题。
- **命令行更完整**：可以直接使用 Git、编译工具、包管理器、Docker 等常用开发工具。
- **适合 AI Agent 工作**：AI Agent 可以直接读取项目文件、搜索代码、运行命令、查看结果，而不是只根据复制粘贴的代码片段猜测。
- **不污染本地电脑**：依赖、工具链、临时文件都在远程工作区中，不需要在自己的电脑上安装很多开发环境。
- **适合长时间任务**：安装依赖、编译项目、跑测试等任务可以放在工作区中执行，不占用本地电脑资源。

对于 C++ 或 Web 开发来说，你可以把它理解成一台已经准备好的远程 Linux 开发机。

## 2. 使用本地 VS Code 连接

推荐优先使用自己电脑上的 VS Code 连接 Coder 工作区。

这样可以继续使用你熟悉的本地 VS Code 配置，例如主题、快捷键、字体和常用设置。同时，你也可以在 VS Code 插件市场中，把需要的插件一键安装到远程工作区。

这种方式的体验接近本地开发，但代码、终端和程序实际都运行在远程 Linux 工作区中。

## 3. 使用网页版 Code 连接

如果你不想安装本地 VS Code，也可以直接使用浏览器打开网页版 Code。

网页版 Code 已经提供了基本配置，包括代码编辑、终端、Git 和常见文件类型支持。它适合快速进入工作区、临时修改代码，或者在没有本地开发环境的电脑上继续工作。

如果你希望网页版 Code 更接近自己的本地 VS Code，可以导入 VS Code Profile：

1. 在本地 VS Code 中打开 **Profiles**；
2. 选择 **Export Profile**；
3. 导出包含设置、快捷键和插件列表的 profile 文件；
4. 在网页版 Code 中导入该 profile。

## 4. 使用 `code .` 打开项目

无论使用本地 VS Code 还是网页版 Code，都可以通过`code .`打开当前目录的编辑器窗口：

```bash
cd ~/projects/my-app
code .
```

## 5. 适合的场景

Coder 工作区适合用于：

- C++ 项目编译和调试；
- Web 前端或后端开发；
- 运行测试；
- 使用 buildkit 构建或运行服务；
- 阅读和理解大型代码库；
- 使用 AI Agent 辅助开发、排错和文档编写。

简单来说，Coder 工作区就是一个统一、干净、适合 AI Agent 使用的 Linux 开发环境。推荐把它作为日常开发入口使用。
